# CI com GitHub Actions — design

> Status: aprovado em 19/09/2026. Escopo pequeno: implementado direto a partir desta spec,
> sem plano separado.

## Objetivo

Automatizar as regras que hoje o `CLAUDE.md` pede para rodar à mão — testes verdes, build sem
warnings, clippy limpo — e acrescentar formatação padronizada (`rustfmt`). Tudo verificado em
Linux, Windows e macOS a cada pull request, antes do merge.

## Fora de escopo

- **CD (entrega contínua).** `sudoku-core` é uma biblioteca pura; não há artefato a publicar.
  O CD entra junto com o módulo Tauri: build do APK a cada tag `v*`, anexado a uma GitHub
  Release.
- Cobertura de testes, auditoria de dependências (`cargo audit`), MSRV fixa.

## Decisões

| Tema | Decisão | Por quê |
|------|---------|---------|
| Plataforma | GitHub Actions | O repositório já está no GitHub; grátis para repositório público |
| Gatilhos | `push` em `master` + qualquer `pull_request` | Evita rodar duas vezes o mesmo código (push da branch + PR) |
| Concorrência | Cancela a execução antiga do mesmo PR/branch | Não gasta minutos com commits já superados |
| Formatação | `rustfmt` com configuração padrão, sem `rustfmt.toml` | Padrão da comunidade; nada a decidir ou manter |
| Sistemas | Matriz Ubuntu + Windows + macOS, `fail-fast: false` | Prepara o terreno do Tauri; vê todos os resultados de uma vez |
| Toolchain | `stable` mais recente (`dtolnay/rust-toolchain`) | Preferência do projeto por versões novas. Custo: lint novo pode deixar o CI vermelho sem mudança de código — corrige-se num `chore` |
| Warnings | `-D warnings` no clippy e `RUSTFLAGS=-D warnings` no build | Torna "sem warnings" uma regra verificada, não um combinado |
| Lockfile | `--locked` | Falha se `Cargo.lock` estiver desatualizado em relação ao `Cargo.toml` |
| Cache | `Swatinem/rust-cache` | Reaproveita dependências compiladas entre execuções |
| Finais de linha | `.gitattributes` com `* text=auto eol=lf` | Mesmo conteúdo em todo SO; evita diff fantasma no Windows |

## Componentes

1. **Commit de formatação** (`chore: format codebase with rustfmt`) — um `cargo fmt` único no
   projeto todo, sem mudança de comportamento.
2. **`.git-blame-ignore-revs`** — lista o hash do commit acima, para `git blame` e GitHub
   atribuírem cada linha ao autor real.
3. **`.gitattributes`** — normalização de finais de linha.
4. **`.github/workflows/ci.yml`** com dois jobs:
   - `fmt` (Ubuntu): `cargo fmt --check`.
   - `test` (matriz de 3 SOs): `cargo clippy --all-targets --locked -- -D warnings`,
     `cargo build --locked`, `cargo test --locked`.
5. **Proteção do `master`** (manual, no GitHub): exigir os jobs do CI verdes para o merge.
   Passo a passo na wiki.

- `CLAUDE.md`: `cargo fmt` entre os comandos; o CI como guardião das regras.

## Verificação

- Local: os mesmos comandos do workflow, na raiz do repositório.
- Remota: o PR de `chore/ci` precisa ficar verde nos 3 SOs.
- Falha proposital: um commit temporário mal formatado deve deixar o job `fmt` vermelho;
  depois é revertido.
